# To Do管理アプリケーション - 受入基準チェックリスト

## 概要

このドキュメントは、To Do管理アプリケーション（MVP版）の受入基準をチェックリスト形式でまとめたものです。各ユーザーストーリーに対応する受入基準を網羅的に記載しています。

**チェック記号の意味**
- [ ] 未確認
- [x] 確認済み・合格
- [!] 不合格・要修正

---

## US-001: タスクの作成

### 基本機能

- [ ] タスク一覧画面にタスク作成フォームが表示される
- [ ] タイトル入力欄（テキストボックス）が表示される
- [ ] 「追加」ボタンが表示される
- [ ] プレースホルダーテキストが適切に表示される（例: "新しいタスクを入力"）

### 正常系

- [ ] タイトルを入力して「追加」ボタンをクリックすると、タスクが作成される
- [ ] 作成後、タスク一覧に新しいタスクが表示される
- [ ] 作成したタスクは「未完了」状態である（チェックボックスが未チェック）
- [ ] タスク作成後、入力欄が空になる
- [ ] タスク作成後、タスク一覧画面にリダイレクトされる（PRGパターン）
- [ ] ブラウザの再読み込みをしても、タスクが重複して作成されない

### バリデーション

- [ ] タイトルが空の場合、エラーメッセージが表示される
- [ ] エラーメッセージの内容: 「タイトルを入力してください」
- [ ] タイトルが空白のみの場合、エラーメッセージが表示される
- [ ] タイトルが255文字以内の場合、正常に作成される
- [ ] タイトルが256文字以上の場合、エラーメッセージが表示される
- [ ] エラーメッセージの内容: 「タイトルは255文字以内で入力してください」
- [ ] バリデーションエラー時、入力した内容が保持される

### データベース

- [ ] タスクがtasksテーブルに正しく保存される
- [ ] id（主キー）が自動採番される
- [ ] titleが正しく保存される
- [ ] completedがfalseで保存される
- [ ] created_atに現在日時が設定される
- [ ] updated_atに現在日時が設定される

### UI/UX

- [ ] フォームの送信中、ボタンが無効化される（二重送信防止、オプション）
- [ ] レスポンシブデザインでモバイルでも正常に動作する
- [ ] エラーメッセージが視覚的にわかりやすく表示される（赤色など）

## US-002: タスクの完了

### 基本機能

- [ ] 各タスクにチェックボックスが表示される
- [ ] チェックボックスは未完了タスクでは未チェック状態である
- [ ] チェックボックスは完了済みタスクではチェック済み状態である

### 正常系

- [ ] 未完了タスクのチェックボックスをクリックすると、完了状態になる
- [ ] 完了済みタスクのチェックボックスをクリックすると、未完了状態になる
- [ ] 完了状態変更後、タスク一覧画面にリダイレクトされる
- [ ] 完了状態が視覚的に区別される（打ち消し線、色の変更など）
- [ ] チェックボックスの変更が即座にデータベースに反映される

### データベース

- [ ] completedフラグが正しく更新される（true ⇔ false）
- [ ] updated_atが現在日時に更新される
- [ ] 他のカラム（id、title、created_at）は変更されない

### UI/UX

- [ ] チェックボックスのクリック領域が適切なサイズである
- [ ] 完了済みタスクのタイトルに打ち消し線が表示される
- [ ] 完了状態の変更がスムーズに行われる（遅延がない）
- [ ] モバイルでもタップしやすいサイズである

## US-003: タスクの一覧表示

### 基本機能

- [ ] タスク一覧画面にアクセスできる（URL: `/` または `/tasks`）
- [ ] すべてのタスクがリスト形式で表示される
- [ ] 各タスク行に以下の要素が含まれる
  - [ ] チェックボックス
  - [ ] タスクタイトル
  - [ ] 編集リンク/ボタン
  - [ ] 削除ボタン

### データ表示

- [ ] タスクが作成日時の降順で表示される（新しいものが上）
- [ ] タスクが0件の場合、「タスクがありません」というメッセージが表示される
- [ ] タスクが複数ある場合、すべて正しく表示される
- [ ] 完了済みタスクと未完了タスクが混在して表示される

### パフォーマンス

- [ ] タスクが100件ある場合でも、1秒以内に表示される
- [ ] ページの読み込みが適切な速度で完了する

### UI/UX

- [ ] ページタイトル（アプリケーション名）が表示される
- [ ] 各タスク行が視覚的に区別できる（区切り線、背景色など）
- [ ] レスポンシブデザインでモバイルでも見やすい
- [ ] スクロールが適切に機能する

## US-004: タスクの削除

### 基本機能

- [ ] 各タスクに削除ボタンが表示される
- [ ] 削除ボタンのラベルが明確である（「削除」または「×」アイコン）

### 正常系

- [ ] 削除ボタンをクリックすると、タスクが削除される
- [ ] 削除後、タスク一覧画面にリダイレクトされる
- [ ] 削除後、タスク一覧から該当タスクが消える
- [ ] 削除は即座にデータベースに反映される

### データベース

- [ ] tasksテーブルから該当レコードが物理削除される
- [ ] 他のタスクには影響がない

### エラーハンドリング

- [ ] 存在しないタスクIDで削除を試みた場合、適切なエラーメッセージが表示される
- [ ] エラー時にはタスク一覧画面にリダイレクトされる

### UI/UX（オプション）

- [ ] 削除前に確認ダイアログが表示される（JavaScriptで実装、オプション）
- [ ] 確認ダイアログで「キャンセル」を選択すると削除されない
- [ ] 削除ボタンが誤クリックされにくい位置・サイズである

## US-005: タスクの編集

### 基本機能

- [ ] 各タスクに編集リンク/ボタンが表示される
- [ ] 編集リンクをクリックすると、タスク編集画面に遷移する
- [ ] タスク編集画面のURL: `/tasks/{id}/edit`

### タスク編集画面の表示

- [ ] ページタイトル「タスクの編集」が表示される
- [ ] タイトル入力欄が表示される
- [ ] 入力欄に現在のタスクタイトルが表示される
- [ ] 「保存」ボタンが表示される
- [ ] 「キャンセル」リンク/ボタンが表示される
- [ ] 「戻る」リンクが表示される

### 正常系（更新）

- [ ] タイトルを変更して「保存」ボタンをクリックすると、タスクが更新される
- [ ] 更新後、タスク一覧画面にリダイレクトされる
- [ ] 更新後、タスク一覧に変更内容が反映される
- [ ] ブラウザの再読み込みをしても、タスクが重複して更新されない

### 正常系（キャンセル）

- [ ] 「キャンセル」をクリックすると、タスク一覧画面に戻る
- [ ] キャンセル時、変更内容は破棄される
- [ ] キャンセル時、データベースは更新されない

### バリデーション

- [ ] タイトルが空の場合、エラーメッセージが表示される
- [ ] エラーメッセージの内容: 「タイトルを入力してください」
- [ ] タイトルが空白のみの場合、エラーメッセージが表示される
- [ ] タイトルが255文字以内の場合、正常に更新される
- [ ] タイトルが256文字以上の場合、エラーメッセージが表示される
- [ ] バリデーションエラー時、入力した内容が保持される
- [ ] バリデーションエラー時、編集画面にとどまる

### データベース

- [ ] titleが正しく更新される
- [ ] updated_atが現在日時に更新される
- [ ] 他のカラム（id、completed、created_at）は変更されない

### エラーハンドリング

- [ ] 存在しないタスクIDで編集画面にアクセスした場合、エラーメッセージが表示される
- [ ] エラーメッセージ: 「タスクが見つかりません」
- [ ] エラー時にはタスク一覧画面にリダイレクトされる

### UI/UX

- [ ] 編集画面のレイアウトが見やすい
- [ ] 入力欄が適切なサイズである
- [ ] ボタンが押しやすい位置・サイズである
- [ ] レスポンシブデザインでモバイルでも使いやすい

## US-006: 完了/未完了の切り替え表示（フィルタリング）

### 基本機能

- [ ] フィルタータブ/ボタンが表示される
- [ ] 「すべて」タブ/ボタンが表示される
- [ ] 「未完了」タブ/ボタンが表示される
- [ ] 「完了済み」タブ/ボタンが表示される

### フィルター機能

- [ ] 「すべて」を選択すると、すべてのタスクが表示される
- [ ] 「未完了」を選択すると、未完了タスクのみが表示される
- [ ] 「完了済み」を選択すると、完了済みタスクのみが表示される
- [ ] フィルター適用後も、タスクは作成日時の降順で表示される

### URLとクエリパラメータ

- [ ] 「すべて」: `/tasks` または `/tasks?filter=all`
- [ ] 「未完了」: `/tasks?filter=active`
- [ ] 「完了済み」: `/tasks?filter=completed`
- [ ] URLを直接入力してもフィルターが適用される
- [ ] ブラウザの戻る/進むボタンでフィルター状態が保持される

### UI/UX

- [ ] 現在選択中のフィルターが視覚的にわかる（ハイライト、アンダーラインなど）
- [ ] フィルターの切り替えがスムーズである
- [ ] フィルター適用後、該当タスクがない場合は適切なメッセージが表示される
  - [ ] 未完了タスクがない場合: 「未完了のタスクがありません」
  - [ ] 完了済みタスクがない場合: 「完了済みのタスクがありません」
- [ ] レスポンシブデザインでモバイルでもタブが使いやすい

### データベース

- [ ] フィルター適用時、適切なSQLクエリが実行される
- [ ] 不要なデータを取得していない（例: 未完了フィルター時に完了済みデータを取得していない）

## 共通項目

### セキュリティ

- [ ] CSRFトークンがすべてのPOSTリクエストに含まれる
- [ ] SQLインジェクションの脆弱性がない（PreparedStatementを使用）
- [ ] XSSの脆弱性がない（Thymeleafの自動エスケープを使用）

### エラーハンドリング

- [ ] 予期しないエラーが発生した場合、適切なエラーページが表示される
- [ ] エラーページに戻るリンクがある
- [ ] エラーログが適切に記録される

### パフォーマンス

- [ ] ページの読み込み時間が2秒以内である
- [ ] データベースクエリが最適化されている
- [ ] 不要なN+1クエリが発生していない

### ブラウザ互換性

- [ ] Chrome（最新版）で正常に動作する
- [ ] Firefox（最新版）で正常に動作する
- [ ] Safari（最新版）で正常に動作する
- [ ] Edge（最新版）で正常に動作する

### レスポンシブデザイン

- [ ] デスクトップ（1920x1080）で正常に表示される
- [ ] タブレット（768x1024）で正常に表示される
- [ ] モバイル（375x667）で正常に表示される
- [ ] 縦向き・横向きの両方で正常に表示される

### アクセシビリティ

- [ ] キーボードのみで操作できる（Tab、Enter、Spaceキー）
- [ ] フォーム要素にラベルが適切に設定されている
- [ ] エラーメッセージが明確で理解しやすい
- [ ] 色だけで情報を伝えていない（色覚障害者への配慮）

### データ整合性

- [ ] 同時に複数のユーザーが操作しても、データの整合性が保たれる
- [ ] トランザクションが適切に管理されている
- [ ] ロールバックが必要な場合、正しくロールバックされる

---

## 非機能要件

### 可用性

- [ ] アプリケーションが24時間稼働できる
- [ ] システムエラーが発生しても、データベースが破損しない

### 保守性

- [ ] コードが適切にコメントされている
- [ ] クラス、メソッド、変数の命名が適切である
- [ ] ログが適切に出力されている
- [ ] 設定ファイルが環境ごとに分離されている

### テスト容易性

- [ ] ユニットテストが作成されている（カバレッジ80%以上）
- [ ] 統合テストが作成されている
- [ ] E2Eテストが作成されている（オプション）
- [ ] テストが自動化されている

## 受入判定基準

### 必須項目（Must Have）

- [ ] US-001〜US-006のすべての基本機能が動作する
- [ ] すべてのバリデーションが正しく機能する
- [ ] データベースへの保存・取得が正常に動作する
- [ ] セキュリティの基本要件を満たしている
- [ ] 主要ブラウザ（Chrome、Firefox、Safari、Edge）で動作する

### 推奨項目（Should Have）

- [ ] レスポンシブデザインが実装されている
- [ ] エラーハンドリングが適切に実装されている
- [ ] パフォーマンスが許容範囲内である
- [ ] ユニットテストのカバレッジが80%以上である

### オプション項目（Could Have）

- [ ] 削除時の確認ダイアログが実装されている
- [ ] アクセシビリティ要件を満たしている
- [ ] E2Eテストが作成されている

## チェックリスト使用方法

### テスト実施者向け

1. 各項目を上から順番にテストする
2. 合格した項目は `[x]` に変更する
3. 不合格の項目は `[!]` に変更し、不具合内容を記録する
4. すべての必須項目が `[x]` になったら受入完了

### 開発者向け

1. 実装前にチェックリストを確認する
2. 各ユーザーストーリーの受入基準を満たすように実装する
3. 自己チェックでテストを実施する
4. チェックリストの項目を満たせない場合は、理由を記録する
